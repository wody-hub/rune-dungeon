# [기획서] 17. MVP 개발 단계표

## 1. 목표
- 첫 프로젝트이자 웹개발자 중심 바이브 코딩 환경을 고려해, `작게 만들고 빨리 검증하는 구조`를 채택한다.
- 첫 MVP의 목적은 대규모 콘텐츠 생산이 아니라 `핵심 플레이 루프 성립 여부`를 확인하는 것이다.
- 따라서 3D 완성도보다 `Phaser 2D 기준의 플레이 가능 프로토타입`을 우선한다.

## 2. 첫 MVP 성공 기준
- 플레이어가 필드에서 이동할 수 있다.
- 기본 공격과 몬스터 피격 처리가 작동한다.
- 몬스터 처치 후 자모 파편 드랍이 발생한다.
- 파편으로 `자형`을 만들고 `결: 글자`까지 진입할 수 있다.
- `인` 1종을 장착하고 변신 on/off가 된다.
- 변신 시 외형 또는 오라 변화가 즉시 눈에 보인다.
- 필드 1개, 던전 1개, 보스 1개가 연결된다.
- 광역 공격 없이 `적 1체를 정확히 상대하는 전투 루프`가 재미있게 작동한다.
- 언령결이 `기본 공격 연동 확률 발동`으로 동작한다.

## 3. 단계별 개발 순서

### 3.1. 0단계: 기술 바닥 만들기
- `Phaser` 프로젝트 기본 구조를 만든다.
- 씬 전환 구조를 `타이틀`, `마을`, `필드`, `던전` 단위로 최소 구성한다.
- 플레이어 입력, 카메라, 충돌, UI 디버그 표시를 붙인다.

### 3.2. 1단계: 플레이어 조작
- 임시 스프라이트로 `8방향 이동`을 구현한다.
- `idle`, `walk`, `attack` 애니메이션 전환을 붙인다.
- 무기 레이어 또는 공격 이펙트 하나를 붙여 전투 감각을 먼저 확인한다.
- 첫 무기군은 `대검계열`을 기준으로 구현한다.
- 공격 모션은 `뒤에서 내려치는 양손 공격` 1종만 먼저 만든다.

### 3.3. 2단계: 기본 전투 루프
- 몬스터 `1종`을 구현한다.
- 첫 전투 루프는 `대검계열 근접 공격` 기준으로 공격 판정을 단순하게 만든다.
- 피격, 체력 감소, 사망, 드랍 생성까지 한 루프로 연결한다.
- 이 단계에서는 반드시 `단일 대상 타기팅`과 `1:1 교전 감각`을 먼저 검증한다.
- 마나는 넣지 않고, 이 단계에서는 물리 전투 루프를 먼저 검증한 뒤 다음 단계에서 언령결의 `확률 발동`을 연결한다.
- MVP 대검 수치는 `공격 모션 길이 1.25초`, `초당 공격 환산 0.8`, `기본 피해 계수 1.45`, `기본 procRateBonus +1%`, `받는 피해 -8%`, `경직 저항 +15%`, `기본 언령결 슬롯 2개`를 기준으로 시작한다.
- 세부 파라미터는 `선딜 320ms`, `후딜 930ms`, `사거리 56px`, `전방 판정 폭 32px`, `피격 경직 220ms`를 1차값으로 사용한다.
- 첫 일반 몬스터는 `먹물 슬라임` 1종으로 시작하고, 수치는 `체력 140`, `이동 속도 42px/초`, `공격 모션 1.4초`, `공격 발생 시점 420ms`, `기본 피해 18`을 사용한다.
- 첫 보스는 `몽당연필 기사단장` 1종으로 시작하고, 수치는 `체력 2200`, `기본 방어력 60`, `기본 피해 42`, `공격 모션 1.8초`, `공격 발생 시점 620ms`, `그로기 10초`를 사용한다.

### 3.4. 3단계: 한글 성장 루프
- 자모 파편 드랍 테이블을 최소 구성한다.
- `자형` 조합 UI를 구현한다.
- `자형 -> 결: 글자` 제작 UI 또는 임시 제작 흐름을 구현한다.
- 진언결/언령결은 소수만 넣고, 먼저 제작과 장착 구조, `언령 발동 확률` 옵션 동작이 맞는지 본다.

### 3.5. 4단계: 인과 변신
- `인` 1속성을 구현한다.
- 비전투 기본폼과 전투 변신폼의 차이를 스프라이트 또는 오라로 표현한다.
- 변신 상태가 전투 성능과 시각 상태 둘 다에 연결되도록 만든다.

### 3.5.1. 소모품 보조 루프
- `숨물`, `결불`, `질숨`, `귀로결` 4종만 우선 구현한다.
- `숨물`은 위기 대응용 회복, `결불`은 짧은 공격 버프, `질숨`은 짧은 속도 버프, `귀로결`은 안전 귀환 수단으로 역할을 고정한다.
- 소모품은 전투 핵심 빌드를 대체하지 않고, `언령결`과 `진언결`이 먼저 보이도록 보수적인 수치로 둔다.

### 3.6. 5단계: 공간 구조 연결
- 마을 `1`, 필드 `1`, 던전 `1`을 연결한다.
- 마을은 비전투 허브, 필드는 파밍 공간, 던전은 수동 보상 공간으로 역할을 분리한다.
- 보스 `1`을 배치해 성장 가속 보상을 준다.

## 4. 아트 제작 우선순위
- 플레이어 기본폼 `1세트`
- 플레이어 전투폼 `1세트`
- 무기 `1종`
- 일반 몬스터 `1종`
- 정예 몬스터 `1종`
- 보스 `1종`
- 필드 타일셋 `1종`
- 던전 타일셋 `1종`
- 파편/결/드랍 아이콘 최소 세트
- 첫 무기 후보는 `양손 검` 또는 `양손 도끼` 중 가독성이 높은 쪽으로 선택한다.

## 4.1. `아르카디아` 수직 슬라이스 MVP 범위표
| 구분 | 포함 범위 | MVP 기준 | 의도 |
| :--- | :--- | :--- | :--- |
| 시작 거점 | `아르카디아` 마을 `1개` | 핵심 NPC, 장비창, 인벤토리, 간단 제작 UI | 모든 루프의 출발/복귀 거점 |
| 필드 | `새벽 들판` `1개` | 일반 몬스터 파밍, 자모 파편 드랍, 이동/전투 검증 | 가장 먼저 도는 기본 사냥 공간 |
| 던전 | `흑심 채굴장` `1개` | 수동 진입, 1~2개 간단 방, 보스방 연결 | 수동 보상 공간 검증 |
| 보스 | `몽당연필 기사단장` `1종` | 약점 노출, 그로기, 속성 세팅 판정 | 보스 루프 최소 검증 |
| 플레이어 | 캐릭터 `1종` | 기본폼, 전투폼, 대검 공격 | 핵심 조작/타격감 검증 |
| 무기 | `대검계열` `1종` | 양손 내려치기 모션 1개 | 첫 전투 감각 고정 |
| 속성/인 | `화` 속성 `1종` | `인` 장착, 변신 on/off | 속성 정체성과 변신 검증 |
| 몬스터 | 일반 `1종`, 정예 `1종`, 보스 `1종` | `먹물 슬라임`, `오타 요정`, `몽당연필 기사단장` | 적 3단계 위협 구조 확인 |
| 성장 재료 | 자모 파편 소수 | `자형` 1~2개 제작 가능량 | 제작 루프 입문 |
| 결 제작 | `자형 -> 결: 글자` | 최소 1회 제작 성공 | 한글 성장 루프 검증 |
| 진언결 | 소수 `2~3개` | 공속/치명/방어 중 일부만 먼저 | 빌드 차이 최소 검증 |
| 언령결 | 소수 `2~3개` | 초반 4티어 기준 확률 발동 | 발동감과 다중 발동 검증 |
| 소모품 | `숨물 / 결불 / 질숨 / 귀로결` | 기본 수치만 적용 | 보조 루프 확인 |
| UI | 최소 UI | 체력, 데미지 숫자, 인벤토리, 제작, 장착 | 플레이 검증에 필요한 정보만 표시 |

- `아르카디아` 전체 3필드 구조를 한 번에 구현하지 않고, 첫 MVP는 `새벽 들판 1개`만 우선 구현한다.
- `흑심 채굴장`도 전체 5층 구현이 아니라 `입장 -> 전투 구간 -> 보스방`의 축약 구조로 먼저 검증한다.
- NPC는 모든 마을 NPC를 다 넣지 않고 `나랏`, `외눈의 묵향`, `각인공`, `잡화상`, `보관지기` 5명만 우선 배치한다.
- 첫 수직 슬라이스의 성공 기준은 콘텐츠 양이 아니라 `전투`, `드랍`, `제작`, `장착`, `변신`, `보스 격파`가 한 흐름으로 이어지는지 여부다.

## 5. 의도적으로 미루는 것
- 전 속성 동시 구현
- 전 티어 외형 동시 제작
- 방어구 부위별 풀 레이어링
- 복잡한 보스 패턴 다수
- 정교한 경제 밸런스
- 멀티플레이 및 채널 시스템
- 3D 카메라와 3D 캐릭터 파이프라인

## 6. 개발 원칙
- 새 기능은 항상 임시 에셋으로 먼저 검증한다.
- 시스템이 살아난 뒤에만 아트 품질을 올린다.
- 모든 것을 한 번에 만들지 않고 `플레이 루프 단위`로 자른다.
- 구현 난이도가 높아지면 표현을 단순화하고 루프 검증을 우선한다.
- 전투는 광역기 전제를 버리고, 단일 대상 교전이 재미있는지부터 증명한다.
