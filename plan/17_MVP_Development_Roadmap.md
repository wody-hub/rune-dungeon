# [기획서] 17. 아르카디아 수직 슬라이스 개발 단계표

## 1. 목표
- 첫 구현은 전체 제품 MVP가 아니라 `아르카디아 수직 슬라이스`다.
- 목적은 아르카디아 `공유 마을 허브`와 구역별 `협동 인스턴스`에서 `전투 -> 드랍 -> 제작 -> 장착 -> 변신 -> 보스 격파` 루프와 서버 권위 상태가 실제로 성립하는지 검증하는 것이다.
- `아르카디아`만 `공유 마을 허브`이며, `음` 파밍을 포함한 모든 게임플레이 구역은 `포털`로 연결되는 최대 4인 `협동 인스턴스`다.
- 제품 전체 방향은 자동/방치 성장과 수동 던전이 결합된 하이브리드 액션 수집 RPG지만, 첫 수직 슬라이스는 온라인 수동 전투와 제작 루프를 먼저 검증한다.
- 고정 아이소메트릭 3D의 플레이 가능 수직 슬라이스와 동기화된 다중 플레이어 상태를 우선한다.

## 2. 성공 기준
- 플레이어가 고정 아이소메트릭 3D 필드에서 서버가 확정한 이동과 바라보기 전환을 할 수 있다.
- 기본 공격과 몬스터 피격 처리가 동작한다.
- 몬스터 처치 후 `음`과 소량 골드 드랍이 발생한다.
- `음`으로 `자형`을 만들고 `결: 글자` 제작까지 진입할 수 있다.
- 진언결과 언령결을 장착하고 기본 효과가 전투에 반영된다.
- 언령결이 `기본 공격 적중 시 확률 발동`으로 동작한다.
- `인` 1종을 장착하고 변신 on/off가 된다.
- 변신 시 외형 또는 오라 변화가 즉시 눈에 보인다.
- `아르카디아 마을 -> 새벽 들판 -> 흑심 채굴장 -> 보스방 -> 아르카디아 마을` 동선이 연결된다.
- 광역 공격 없이 `적 1체를 정확히 상대하는 전투 루프`가 재미있게 작동한다.
- 게스트 닉네임으로 입장한 두 플레이어가 같은 아르카디아 마을에서 서로의 이동을 관찰할 수 있다.
- 서버가 잘못된 이동, 전투, 습득, 제작 요청을 거절하고 재접속 후에도 서버 소유 진행을 보존한다.

## 3. 개발 순서

### 3.1. 0단계: 온라인 기술 바닥 만들기
- 클라이언트는 `Svelte + TypeScript + Vite + Three.js/Threlte`, 서버는 `Rust + WebSocket` 기본 구조를 만든다.
- 고정 아이소메트릭 카메라, 제한 줌, 공유 마을 허브와 협동 인스턴스의 포털/입장 트리거 전환, UI 디버그 표시를 붙인다.
- 게스트 닉네임 입장과 서버 발급 플레이어 ID·세션을 구현한다.
- 클라이언트는 이동·공격·습득·제작·변신 의도를 보내고, 서버는 위치·전투·드랍·인벤토리·제작 결과·변신을 확정한다.
- `localStorage`는 비권위 그래픽·입력·UI 환경설정에만 사용할 수 있으며 게임 진행 저장에는 사용할 수 없다.

### 3.2. 1단계: 플레이어 조작
- 임시 저폴리 모델과 리그로 서버 동기화 이동을 구현한다.
- 첫 MVP는 `idle`, `walk`, `attack` 애니메이션만 우선 구현한다.
- `hit`, `death`는 피격 피드백 검증 이후 확장한다.

### 3.3. 2단계: 기본 전투
- 첫 무기군은 `대검계열` 1종으로 시작한다.
- 기본 공격은 단일 대상 1체 판정을 사용한다.
- 마나는 넣지 않는다.
- 대검 수치는 `공격 모션 길이 1.25초`, `초당 공격 환산 0.8`, `기본 피해 계수 1.45`, `기본 procRateBonus +1%`, `받는 피해 -8%`, `경직 저항 +15%`, `기본 언령결 슬롯 2개`를 기준으로 한다.
- 세부 파라미터는 `선딜 320ms`, `후딜 930ms`, `사거리 56px`, `전방 판정 폭 32px`, `피격 경직 220ms`를 1차값으로 사용한다.
- 대검의 `24~32`는 무기 공격력 굴림과 STR 보너스를 더한 피해 계수 적용 전 범위이며, 비치명타 방어력 계산 전 범위는 `34.8~46.4`다. 기본 치명타를 반영한 평균 기대 피해 `41.615`는 방어력 적용 전 기준으로 서버 검증에 사용한다.
- 첫 일반 몬스터는 `먹물 슬라임` 1종으로 시작하고, 수치는 `체력 140`, `이동 속도 42px/초`, `공격 모션 1.4초`, `공격 발생 시점 420ms`, `기본 피해 18`을 사용한다.
- 첫 정예 몬스터는 `오타 요정` 1종으로 시작하고, 수치는 `체력 320`, `이동 속도 68px/초`, `공격 모션 1.05초`, `공격 발생 시점 260ms`, `기본 피해 28`을 사용한다.
- 첫 보스는 `몽당연필 기사단장` 1종으로 시작하고, 수치는 `체력 2200`, `기본 방어력 60`, `기본 피해 42`, `공격 모션 1.8초`, `공격 발생 시점 620ms`, `약점 노출 4초`, `그로기 10초`를 사용한다.
- 몬스터 체력은 첫 서버 전투 테스트의 관측 처치 시간 전까지 현재 값을 유지한다. 특히 보스의 약점 노출/그로기 주기는 플레이테스트로 보정하며, 문서에서 고정 처치 타수를 목표로 삼지 않는다.

### 3.4. 3단계: 한글 성장 루프
- `음` 드랍은 서버 판정 `eumRollGroup`으로 구성한다. 현재 모든 그룹은 `allowDuplicateSymbols: false`이며, 먹물 슬라임은 `1~2회`, 오타 요정은 `2~4회`, 몽당연필 기사단장은 `3~5회`를 가중치 풀에서 중복 없이 뽑는다. 각 선택 뒤에는 뽑힌 기호를 남은 가중치 풀에서 제거하므로 한 보상에 같은 음 기호가 두 번 포함되지 않는다. 골드·아이템은 확률과 정수 수량 범위, 보장 여부를 가진 `entries`로 분리한다.
- `자형` 조합을 구현한다. 첫 `자형: 화`는 `음 · ㅎ ×1 + 음 · ㅘ ×1`, 성공률 `100%`, 실패 시 입력 미소모로 고정한다.
- `자형 -> 결: 글자` 제작 UI 또는 임시 제작 흐름을 구현한다. 첫 `결: 화`는 `자형: 화 ×1`, 성공률 `95%`, 실패 시 입력 소모·출력 없음으로 고정하며, 첫 두 레시피는 `goldCost: 0`, 빈 촉매/보조 재료 목록과 실패 입력 소모 정책을 명시한다.
- 진언결 `2~3개`, 언령결 `2개`만 먼저 넣고, 제작과 장착 루프를 검증한다.
- 언령결은 기본 공격 적중 시 장착한 언령결마다 독립 확률 판정을 수행한다.

### 3.5. 4단계: 인과 변신
- `인: 움결 화` 1종을 구현한다.
- 변신 on/off를 구현한다.
- 기본폼과 전투폼은 완성 모델이 없어도 메시, 색상, 오라, 실루엣 차이로 구분한다.
- 중심 마을 변신 제한 규칙은 첫 구현에서는 경고 텍스트 또는 간단한 비활성화 처리로만 검증한다.

### 3.6. 5단계: 보스 루프
- `몽당연필 기사단장`은 평상시 피해 감소, 약점 노출, 그로기 상태를 가진다.
- 약점 노출 상태에서는 화염 언령이 확정 발동하거나 사실상 보장되는 예외 규칙을 둘 수 있다.
- 보스 처치 후 보상 드랍과 마을 귀환 포탈이 열린다.

## 5. 구현 체크리스트

### 5.1. 필수
- Svelte/Threlte 클라이언트와 Rust/WebSocket 서버가 연결되고, 고정 아이소메트릭 3D 월드 전환이 동작한다.
- 두 게스트 플레이어가 공유 아르카디아에서 동기화된 이동을 관찰한다.
- `아르카디아` 마을 `1개`, `새벽 들판` `1개`, 축약형 `흑심 채굴장` `1개`가 연결된다.
- 플레이어의 서버 동기화 이동과 `idle/walk/attack` 전환이 된다.
- 대검 기본 공격 `1종`과 피격 처리, 데미지 숫자, 치명타 표시가 동작한다.
- 일반 몬스터 `먹물 슬라임`, 정예 몬스터 `오타 요정`, 보스 `몽당연필 기사단장`이 배치된다.
- `음` 드랍과 습득이 서버 권위로 처리된다.
- `자형 -> 결: 글자` 최소 1회 제작이 가능하다.
- 진언결 `2~3개`, 언령결 `2개` 장착과 효과 적용이 된다.
- `인` 1속성 장착과 변신 on/off가 된다.
- `숨물 / 결불 / 질숨 / 귀로결` 4종이 기본 수치로 동작한다.
- 보스 약점 노출과 그로기 루프가 실제 전투에서 검증된다.

### 5.2. 있으면 좋음
- 마을 핵심 NPC `5명`의 기본 기능이 모두 열린다.
- 간단한 퀘스트 또는 가이드 흐름이 붙어 첫 제작과 첫 보스까지 안내한다.
- 드랍 아이템 아이콘, `음` 아이콘, 기본 오라가 붙는다.
- 연결 해제 후 재접속해 서버 소유 인벤토리와 장착 상태가 유지된다.
- 정예 몬스터 전용 보상이나 하위 촉매 드랍이 붙는다.

### 5.3. 후속 범위
- OAuth와 계정 복구
- 절차적 월드 생성, 하우징, 거래, 파티/길드, AI 에이전트
- 자동/오프라인 보상과 운영 경제
- `아르카디아`의 나머지 필드 `2개`
- `흑심 채굴장` 전체 `5층`
- 추가 속성 `인`
- 활/지팡이 무기군
- 고급 드랍 테이블 세분화
- 상위 진언결/언령결 대량 라인업

## 6. 최소 UI 화면 목록

| 화면 | 필수 요소 | MVP 목적 |
| :--- | :--- | :--- |
| `HUD` | 플레이어 HP, 현재 무기, 변신 상태, 소모품 퀵슬롯, 데미지 숫자 | 전투와 생존 정보 즉시 확인 |
| `인벤토리` | `음` 수량, 일반 아이템, 소모품 목록 | 파밍 결과 확인 |
| `장착` | 무기, 진언결 슬롯, 언령결 슬롯, `인` 장착 상태 | 전투 세팅 확인과 교체 |
| `제작` | `자형` 조합, `결: 글자` 제작, 재료 요구 수량 | 한글 성장 루프 검증 |
| `변신` | 현재 `인`, 전투폼 on/off, 속성 표시 | 변신과 속성 정체성 확인 |
| `보스 UI` | 보스 HP, 약점 노출 상태, 그로기 상태 | 보스 기믹 가시화 |

- `HUD`는 항상 열려 있는 전투 화면 기준 UI다.
- `인벤토리`, `장착`, `제작`, `변신`은 분리된 패널이거나 한 화면 안의 탭 구조여도 된다.
- 첫 수직 슬라이스에서는 `상점`, `도감`, `길드`, `채널 선택`, `설정 세분화` 같은 화면을 만들지 않는다.
- UI는 화려함보다 `읽히는 것`, `조작 가능한 것`, `루프 검증 가능한 것`을 우선한다.

| `아르카디아 마을` | `새벽 들판` | 필드 출구 포털 또는 이동 관리인 | 같은 파티 또는 초대된 게스트의 협동 인스턴스를 생성해 비전투 상태에서 입장 |
| `새벽 들판` | `아르카디아 마을` | 마을 귀환 포털 | 전투 중이 아니면 공유 마을 허브로 즉시 전환 |
| `새벽 들판` | `흑심 채굴장 입구` | 던전 입장 포털 | 입장 확인 후 같은 그룹의 협동 인스턴스로 전환 |
| `흑심 채굴장 전투 구간` | `보스방` | 전투 구간 클리어 후 입장 트리거 개방 | 몬스터 정리 시 같은 그룹의 보스방 인스턴스를 생성 |
| `흑심 채굴장` | `아르카디아 마을` | `귀로결` 또는 던전 탈출 포털 | `귀로결`은 전투 중 사용 불가 |
| `보스방` | `아르카디아 마을` | 보스 처치 후 귀환 포털 | 보스 처치 시 귀환 포털 활성화 |

- 첫 수직 슬라이스는 연속형 월드 생성 대신, 서버가 검증하는 포털/입장 트리거 기반의 허브-인스턴스 전환으로 고정한다.
- 마을과 필드는 왕복이 쉬워야 하므로 즉시 전환을 허용한다.
- 던전 입장은 확인 단계를 두고, 보스방 진입은 전투 구간 클리어를 조건으로 둔다.
- `귀로결`은 마을 복귀 전용이며, 던전 진행 스킵 수단이 아니라 안전 귀환 수단으로 취급한다.

## 9. 개발 원칙
- 새 기능은 항상 임시 에셋으로 먼저 검증한다.
- 시스템이 살아난 뒤 아트 품질을 올린다.
- 수치와 콘텐츠 JSON은 서버가 시작 전에 검증하며, 클라이언트 사본은 표시용이다.
- 첫 구현은 재미·조작·온라인 서버 권위 검증을 함께 우선한다.
