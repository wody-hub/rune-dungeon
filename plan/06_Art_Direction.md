# [기획서] 06. 아트 디렉션 및 비주얼 컨셉 (Art Direction)

## 1. 핵심 비주얼 테마: "먹빛 결정 (Inkbound Crystal)"
- **모티브:** `엘리멘탈 사가`에 가까운 미래 아포칼립스 판타지 + 먹·한지의 흔적 + 결의 에너지 아트
- **핵심 문장:** 먹빛 세계는 빛을 죽이는 배경이고, 결의 발광은 살아 있음을 증명하는 주인공이다.
- **재질 역할:** 금속과 결정은 세계·캐릭터의 물성으로, 한지와 먹은 UI 가장자리와 각인·변신 연출의 질감으로 사용한다.
- **색상 전략 (Color Palette):**
  - **배경:** 차가운 네이비, 먹빛 회색, 먼지 낀 청록, 붉게 죽은 하늘빛
  - **핵심 요소:** 속성별 결 광채, 청백/주홍/금빛 에너지선, 갑주 틈의 발광

---

## 2. 캐릭터 및 오브젝트 디자인
- **캐릭터 비율:** 날렵한 비율의 SD~세미디포르메 스타일
- **텍스처:** 손그림 질감보다 금속성, 결정성, 결 에너지의 질감을 우선
- **광원 연출 (Lighting):**
  - 캐릭터 중심의 약한 개인 광원 유지
  - 세계는 황폐하지만 캐릭터와 결은 선명하게 보여야 함
- **표현 방식:** 첫 구현은 `Three.js/Threlte`의 저폴리 3D 모델, 리그, 머티리얼 기반으로 접근한다.
- **시점:** 고정 아이소메트릭 3D 카메라와 제한된 줌을 사용하며 자유 카메라는 제공하지 않는다.
- **자산 크기 원칙:** 공유 허브와 최대 4인 인스턴스에서 읽히는 실루엣과 원근 가독성을 우선 검증하며, 카메라 거리에서 인물·무기·오라가 구분되게 한다.
- **월드 표현 범위:** `아르카디아`만 `공유 마을 허브`이며, `음` 파밍을 포함한 모든 게임플레이 구역은 `포털`로 연결되는 `협동 인스턴스`다.

### 2.1. 캐릭터 제작 원칙
- 플레이어의 기본 리그 애니메이션은 `idle`, `walk`, `attack`을 우선 제작한다.
- `hit`, `death`는 1차 전투 감각 검증 이후 확장한다.
- 비전투 상태는 `기본형`, 전투 상태는 현재 인이 활성화된 `변신형`으로 읽히게 한다.
- 성장 등급과 장착 아이템은 외형을 바꾸지 않는다. 외형 상태 전환은 변신 단계로만 결정한다.

### 2.2. 레이어 구성 원칙
- 캐릭터 표현은 `기본 3D 몸체와 고정 의상·경갑`, `변신 단계 메시`, `무기 메시`, `상태 머티리얼`, `속성 오라/VFX` 레이어로 구성한다.
- 첫 MVP는 `단일 캐릭터 메시 + 단일 무기 메시 + 두 상태 머티리얼 + 오라`로 고정한다.
- 인벤토리에서 착용하는 방어구는 외형화하지 않으며, 고정 의상·경갑은 캐릭터 모델의 일부이지 착용 방어구 아이템이 아니다.
- 레벨·티어·장비 교체로 캐릭터 메시나 머티리얼을 바꾸지 않는다.

- **기본 의상·경갑:** 가난한 아르카디아 용병의 고정 외형과 수선 흔적. 항상 같은 인물로 읽히게 한다.
- **1단계 변신형:** MVP에서는 기본형과 같은 메시·실루엣을 유지하고 상태 머티리얼, 발광 문양, 무기 발광, 오라/VFX만 활성화한다.
- **상위 변신형:** 후속 2~4단계는 실루엣이 달라지는 별도 스킨드 메시를 허용하되 동일한 공통 리그, 본 이름, 애니메이션 클립, 무기 소켓 계약을 유지한다.
- **착용 방어구:** 스탯 장비. 게임 내 캐릭터 모델이나 스킨을 교체하지 않는다.

### 2.3. AI 에셋 활용 원칙
- AI 생성 결과물은 초안 제작 도구로만 사용한다.
- 실루엣·토폴로지·리그 품질과 머티리얼 일관성 문제 때문에 반드시 수동 보정 단계를 거친다.
- 무료 에셋과 AI 생성 에셋을 혼합해도 되지만, 최종 게임 내에서는 톤과 비율을 맞춘다.

### 2.4. 플레이어 캐릭터 제작 파이프라인
- OpenMMO의 검증된 제작 순서를 참고하되, 코드·에셋·캐릭터 조형은 복사하지 않고 Rune Dungeon 전용 결과물로 제작한다.
- 첫 제작 대상은 커스터마이징 프리셋이 없는 시그니처 주인공 `1종`이며, 기본형과 `인: 움결 화` 전투형이 같은 인물과 리그로 읽혀야 한다.
- 제작 순서는 다음과 같이 고정한다.
  1. 캐릭터 방향 비교 이미지에서 얼굴, 비율, 고정 의상·경갑, 대검, 동일 메시로 표현하는 기본형과 화염 변신형을 승인한다.
  2. 승인안을 기준으로 정면·측면·후면 턴어라운드와 A 포즈 이미지를 만든다.
  3. Blender에서 승인된 A 포즈를 기준으로 단순 저폴리 캐릭터와 대검을 직접 모델링한다.
  4. Blender에서 SD~세미디포르메 비율, 얼굴, 대검 실루엣, 결정 이음새, 의상 겹침, 토폴로지, UV, 기본형/변신형 머티리얼, 원점과 스케일을 정리한다.
  5. Mixamo에서 휴머노이드 리깅과 MVP 애니메이션 `idle`, `walk`, `attack`을 준비하고, Blender에서 본·가중치·발 미끄러짐·대검 손잡이를 최종 보정한다.
  6. 캐릭터와 대검을 GLB로 내보내 Three.js/Threlte에서 로드하고, 실제 고정 아이소메트릭 카메라 거리에서 실루엣과 애니메이션을 검증한다.
  7. 먹선, 화염 오라, 무기 궤적, 결정 발광은 Three.js/Threlte의 머티리얼·파티클·VFX 레이어로 구현한다.
- 현재 진행 범위는 위 순서의 `1~2`에 해당하는 디자인 승인 게이트까지다. `3~5`의 3D 에셋 제작과 `6~7`의 게임 통합은 디자인 승인 이후의 별도 후속 작업이다.
- 첫 제작은 Blender와 Mixamo의 무료 범위에서 전체 파이프라인을 완주한 뒤 실제 게임 화면의 품질을 평가한다. 실루엣, 재질, 리그 또는 애니메이션 품질이 기준에 미달할 때만 Blender에서 단순 형상을 재작업한다.
- 현재 A안의 기본형과 화염 1단계 변신형은 단일 몸체 메시와 공통 리그를 사용한다. 후속 2~4단계 변신형은 등급·장비 외형과 무관한 별도 전신 메시로 실루엣을 바꿀 수 있다.
- 상위 변신 메시를 하나의 GLB에 선택 메시로 묶을지 단계별 GLB로 분리할지는 2단계 변신 구현 계획에서 성능·로딩 예산과 함께 결정한다.

### 2.4.1. 게이트 A 산출물 및 승인 계약

게이트 A는 구두 또는 대화상 선택으로 끝내지 않는다. 승인한 이미지와 판정 근거를 다음 두 단계로 고정하며, 게이트 B는 A2까지 통과한 버전만 입력으로 사용한다.

| 단계 | 필수 산출물 | 저장 위치 | 통과 기준 |
| :--- | :--- | :--- | :--- |
| `A1 방향 승인` | 비교 이미지 `1장 이상`, 선택안 ID, 기본형·`인: 움결 화` 1단계 변신형·대검의 방향 메모 | `art/source/characters/concept/` | 가난한 아르카디아 용병, 엘프형 아람인, 고정 의상·경갑, 대검 실루엣, MVP 단일 메시 변신 구조와 금지 요소가 정본·아트 가드레일과 일치 |
| `A2 제작 시트 승인` | MVP 단일 캐릭터 메시의 정면/측면/후면 턴어라운드, A 포즈, 대검 시트, 기본형/1단계 변신형 색상·재질 시트 | `art/source/characters/turnaround/` | 두 MVP 상태가 같은 메시·실루엣·공통 리그로 읽히며, 고정 아이소메트릭 축소 보기에서 발광 문양·무기 발광·오라로 1단계 변신 여부가 읽힘 |

- 파일명은 `mvp-aram-<산출물>-vNN.<확장자>` 형식으로 통일한다. 예: `mvp-aram-direction-v01.png`, `mvp-aram-turnaround-v02.png`.
- A1 또는 A2의 승인본은 `docs/assets/characters.md`에 파일명, 버전, 상태(`후보`/`승인`/`미사용`), 결정 날짜, 생성 도구·등급, 출처·라이선스, 승인 근거를 기록한다.
- 대화에서 생성됐지만 저장소에 원본 파일이 없는 이미지는 승인본으로 사용하지 않는다. 원본을 프로젝트에 저장한 뒤 기록을 남기거나, 원본을 다시 첨부해 저장 가능한 파일로 만든다.
- A2 승인 시점에는 얼굴·귀·체형, 수선 흔적, 고정 의상·경갑, 결정 이음새, 대검, 기본형·화염 변신형의 색상/재질이 모두 잠겨야 한다. Paperdoll·리깅·애니메이션·GLB·인게임 VFX 품질 판정은 게이트 A 범위가 아니다.
- 승인 후 수정이 필요하면 기존 파일을 덮어쓰지 않고 새 버전을 저장하며, 이전 버전은 `미사용`으로 표시한다.

### 2.5. 도구 비용·라이선스 및 출처 기록
- Blender와 GLB/glTF 형식은 별도 구매 비용 없이 사용한다. Blender로 제작한 게임 에셋은 Blender의 GPL 때문에 GPL 결과물이 되지 않는다.
- Three.js는 MIT 라이선스 고지를 보존하며 상업용으로 사용한다.
- Mixamo는 무료·로열티 없는 게임 내 이용을 전제로 사용하되, 원본 애니메이션 파일을 단독 재배포하지 않는다.
- 현재 캐릭터 3D 제작에는 Meshy·Tripo 같은 생성형 3D 서비스를 사용하지 않는다. 도입이 필요해지면 비용·공개 정책·라이선스를 별도 승인한다.
- 외부 에셋 또는 AI 생성 에셋을 프로젝트에 처음 추가할 때 `docs/assets/characters.md`에 파일명, 출처, 라이선스, 사용 도구와 등급, 생성·수정 날짜를 기록한다. 사용하지 않게 된 항목은 삭제하지 않고 `미사용`으로 표시한다.

## 3. 결의 광채 (Glowing Aesthetics)
단순한 마법광이 아니라, 무너진 세계에서 살아남은 결의 에너지가 장비와 신체를 통해 새어 나오는 느낌을 구현한다.

### 3.1. 룬과 아이템의 발광 (Emissive Glow)
- **음 드랍:** 길바닥에 떨어진 `음 · ㄱ`, `음 · ㅏ` 등은 각각의 고유한 색으로 부드럽게 깜빡임(Breathing Effect).
- **진언결 완성:** 단어가 각인되어 진언결이 완성되면, 해당 장비 주위에 화려한 '빛의 띠'가 감돌며 존재감을 과시함.

### 3.2. 환경 연출 (Environment)
- **환경:** 무너진 유적, 침식된 도시, 균열 난 평원, 붕괴된 하늘 아래 남은 결의 흔적
- **포스트 프로세싱:** 화면 전체 블룸은 유지하되, 지나치게 포근하지 않고 차갑고 선명한 발광을 강조
- **3D 구현 메모:** 과한 후처리보다 emissive 머티리얼, 절제된 블룸, 오라/VFX 잔광으로 분위기를 만든다. 고정 카메라에서 다른 플레이어와 몬스터가 겹쳐도 전투 정보를 읽을 수 있게 깊이와 색 대비를 관리한다.

## 4. UI 및 가시성 (UI Visibility)
- **표면 활용:** 반투명한 먹빛 금속 패널에 얇은 한지 결·먹 테두리를 제한적으로 사용한다.
- **가독성:** 배경은 황폐하고 어둡지만, 결 글자와 속성 색은 항상 선명하게 유지
- **발광 원칙:** 무기·결정·음은 평상시 약하게 맥동하고 공격·획득·각인·변신 순간에 강해진다. 발광은 장식이 아니라 게임 상태 언어로 사용한다.
- **MVP UI 우선순위:** `HUD`, `인벤토리`, `장착`, `제작`, `변신`, `보스 UI`만 먼저 구현
- **전투 UI 원칙:** 데미지 숫자, 치명타 강조, 보스 약점 노출은 순간적으로 읽혀야 하며 오래 화면을 덮지 않게 한다

## 5. 캐릭터 디자인 상태
- 현재 확정된 것은 날렵한 SD~세미디포르메 비율, 먹빛 금속 몸체, 결정 이음새, 무기·결의 실루엣 가독성까지다.
- 얼굴, 정확한 체형, 의상, 갑주, 무기 조형, 변신 전후 최종 외형은 별도 캐릭터 디자인 단계에서 결정한다.
- 기능 검증용 막대형·기본 도형 캐릭터는 HUD와 발광 검증용 임시 에셋이며 최종 디자인으로 간주하지 않는다.
