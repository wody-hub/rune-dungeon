# Design Data

이 디렉터리는 `plan/` 문서에서 구현 후보 데이터를 뽑아 둔 정규 JSON 보관소다.

## 파일

| 파일 | 기준 문서 | 용도 |
| :--- | :--- | :--- |
| `gyeol-balance.json` | `plan/09_Data_Sheet_Runes.md` | 자형, 결: 글자, 진언결, 언령결, 발동률, 무기군 발동 기준, 보호/촉매 재료 |
| `client/src/game/data/crafting-recipes.json` | `plan/03_Item_and_Equipment.md` | 서버가 판정하는 첫 제작 레시피와 실패 처리 |

## 규칙

- `plan/` 문서가 기획 원본이다.
- `data/design/*.json`은 구현 전환을 위한 정규화 데이터다.
- `data/design/*.json`에는 후보 데이터, 후반 데이터, 수치 미정 항목이 남을 수 있다.
- 현재 `client/src/game/data`는 서버 구현 전 계약 검증을 위한 전환용 fixture다.
- 서버 구현 단계에서는 `shared/content`를 서버 정본으로 두고, 검증된 정본에서 클라이언트 표시용 사본을 생성한다.
- 확률은 `0.03`, `0.2` 같은 소수로 저장한다.
- UI 표기는 클라이언트에서 `%` 문자열로 변환한다.
- 런타임 골드·아이템 드랍은 `entries`로 저장하며, 각 항목은 확률 `(0, 1]`, 정수 수량 범위, 보장 여부를 명시한다. `음` 보상은 `eumRollGroup`의 뽑기 횟수와 가중치 풀로 저장하며, `fragments`는 필요할 때만 내부 호환 wire 필드로 남긴다.
- 런타임 제작 레시피는 입력 외에 골드 비용, 촉매 목록, 허용 보조 재료 목록, 성공률과 실패 시 입력 소모 여부 및 선택적 실패 출력까지 명시하며, 결과는 서버가 확정한다. 비용이나 목록이 없을 때도 `0`과 빈 배열로 명시한다.

## 런타임 데이터와의 차이

| 구분 | 위치 | 허용 범위 |
| :--- | :--- | :--- |
| 기획 정규화 데이터 | `data/design/*.json` | 후보/후반 콘텐츠, 설명문, 수치 미정 항목 |
| 런타임 전환 fixture | `client/src/game/data/*.json` | 첫 수직 슬라이스 계약 검증용 확정값; 이후 서버 정본에서 생성 |
| 서버 정본 콘텐츠 | `shared/content` | 서버가 시작 전에 검증하고 보상·제작·월드 상태 판정에 사용하는 원본 |

런타임 데이터에는 `null` 수치, 타입에 없는 enum, 참조되지 않는 장착 ID를 넣지 않는다.
현재 런타임 데이터 검증은 `node scripts/validate-runtime-data.mjs`로 수행한다.
