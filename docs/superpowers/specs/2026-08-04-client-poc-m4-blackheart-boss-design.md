# Client POC M4 — 흑심 채굴장과 몽당연필 기사단장

## 목표

완료된 M3 체크포인트(`결: 화` 장착, `인: 움결 화` 사용 가능)에서 시작해, 한 번의 짧은 로컬 플레이 흐름으로 아래를 검증한다.

```text
오타 요정 처치 → 기존 드랍 확인 → 보스 문 개방 → 보스방 진입
→ 단단한 심 파훼 → 그로기 → 몽당연필 기사단장 격파
```

이 단계는 서버·저장·멀티플레이를 만들지 않는다. 현재 클라이언트 단독 POC 안에서 전투, 드랍, 변신, 보스 기믹, 목표 안내가 함께 성립하는지를 확인한다.

## 확정 범위

### 시작 상태

- 새 실행은 `흑심 채굴장`의 M4 시나리오에서 시작한다.
- 플레이어는 `결: 화`를 현재 결에 장착했고, `화 변신`은 비활성 상태지만 즉시 켜고 끌 수 있다.
- 시나리오는 M3의 기존 진행 모듈을 재구현하지 않는다. 완료된 M3 상태를 명시적으로 시드하며, 채굴장에는 각인 보급함·재료 수집·자형/결 제작 단계를 배치하지 않는다.
- M3의 수집·제작·장착·변신 규칙과 단위 테스트는 유지한다. M4 화면에서는 완료 상태에 필요한 `현재 결 · 화`와 변신 토글만 보여 준다.

### 지역과 문

- 하나의 `WorldState` 안에 `blackheart_mine`과 `pencil_knight_boss_room`의 두 로컬 지역 상태를 둔다. `world-content.json`의 기존 지역·포털 식별자를 사용하되, 실제 맵 로더나 네트워크 전환은 만들지 않는다.
- 채굴장에는 기능 검증용 `오타 요정` 1체와 보스 문 1개만 둔다.
- 오타 요정의 첫 처치가 문을 영구히 연다. 처치 이후에도 정예는 기존 5초 재스폰 규칙을 유지한다. 열린 문은 재스폰으로 다시 잠기지 않는다.
- 잠긴 문을 누르면 현재 목표 안내만 유지하며 지역을 바꾸지 않는다. 열린 문을 누르면 플레이어의 이동·타깃·자동공격을 정리하고 보스방 시작 위치로 옮긴다.
- M4에는 보스방에서 채굴장·마을로 돌아가는 이동, 로딩 화면, 인스턴스 목록, 저장/복구를 넣지 않는다.

### 드랍과 의뢰 안내

- 오타 요정과 보스는 현재 `monsters.json`의 골드·`음` 드랍 테이블을 사용한다. 현재 자원 HUD에 수량이 반영된다.
- 기존 POC가 아직 처리하지 않는 선택적 `ITEM` 드랍의 표시·사용·인벤토리 UI는 이번 범위에 추가하지 않는다.
- 목표는 첫 20분 스토리 팩의 대형 의뢰 「길드 의뢰 제1호 — 흑심 채굴장의 기사단장」을 압축해 표현한다. 처치 수·수집 수·단계 체크리스트는 만들지 않는다.
- 목표 문구는 서술형으로만 갱신한다: 채굴장 초입의 정예 안내, 문 개방 후 최심부 안내, 보스방의 화 변신 힌트, 격파 후 의뢰 완료.

## 보스 전투 계약

보스는 기존 `몬스터 추적 → 근접 반격` 기반 위에서, 아래의 단일 상태 루프만 추가한다. 투사체, 소환, 범위 공격, 별도 스킬바, 플레이어 사망/부활은 제외한다.

| 상태 | 지속·규칙 | 플레이어 피드백 |
| --- | --- | --- |
| `armored` / 단단한 심 | 보스 기본 방어력 `60`과 기존 `incomingDamageMultiplier: 0.5`를 적용한다. 보스는 기존 추적·반격을 수행한다. 보스방 진입과 각 실패/그로기 후 `6초`간 유지한다. | `단단한 심` 텍스트와 남은 시간 |
| `exposed` / 약점 노출 | `4초`간 유지한다. 변신하지 않은 공격은 그로기를 열지 못한다. 종료 시 단단한 심으로 돌아간다. | `약점 노출` 텍스트, 남은 시간, 화 변신 힌트 |
| `groggy` / 그로기 | 화 변신이 켜진 플레이어의 첫 적중으로 즉시 시작한다. `10초` 동안 방어력을 `0`으로 덮어쓰고 평상시 피해 감소를 해제해 전체 피해를 받는다. 보스의 추적·반격을 멈춘다. 종료 시 단단한 심으로 돌아간다. | `그로기` 텍스트와 남은 시간 |
| `cleared` / 격파 | 보스 HP가 0이 되면 골드·`음` 보상을 한 번 지급하고 의뢰 완료를 고정한다. 이 실행 동안 보스는 재스폰하지 않는다. | `의뢰 완료`와 보스 처치 상태 |

- `weaknessExposeDurationMs: 4000`, `groggyDurationMs: 10000`, `groggyDefenseOverride: 0`, 화 속성 요구는 기존 보스 fixture의 `bossStateModifiers`를 기준으로 한다.
- 단단한 심의 `incomingDamageMultiplier: 0.5`는 기존 방어력 계산 뒤에 적용한다. 그로기에서는 이 값을 `1`로 취급해 방어력 `0`과 함께 전체 피해를 받는다.
- `6초`의 단단한 심 대기만 M4 시나리오 상수다. 이는 고정 처치 시간 목표가 아니라, 약점 4초와 그로기 10초를 화면에서 반복 검증할 최소 간격이다.
- 화 변신은 M3에서 이미 구현된 on/off 상태를 그대로 사용한다. 약점 노출 동안 화 변신이 활성화된 공격이 실제로 적중해야 그로기가 열린다. 변신을 단순 외형 버프로 처리하지 않는다.
- 보스 격파는 대형 의뢰의 완료 조건이므로 재스폰하지 않는다. 일반/정예의 기존 재스폰 동작은 유지하며, 새 실행에서만 보스 시나리오가 초기화된다.

## UI와 비주얼 계약

- 타깃 HUD 바로 아래에 승인된 독립 목표 스트립을 둔다. 이 스트립은 짧은 의뢰 힌트만 담고, M3 제작 상태와 섞지 않는다.
- 보스가 선택되면 상단 중앙 타깃 HUD는 이름·HP·보스 상태·남은 시간을 함께 표시한다. 상태는 색뿐 아니라 텍스트와 테두리/실루엣 변화로 구별한다.
- 하단 중앙의 M3 패널은 완료된 `결: 화`의 상태와 `화 변신` 토글만 표시한다. 완료된 체크포인트에 재료 요구량이나 제작 행동을 다시 노출하지 않는다.
- 자원 HUD는 기존 위치·역할을 유지한다. 최근 드랍 전용 패널, 신규 인벤토리, 보상 선택창은 만들지 않는다.
- 문은 닫혔을 때 억제된 먹빛 금속과 텍스트, 열렸을 때 결정색 상호작용광과 텍스트를 함께 사용한다.
- 정예와 보스는 기능·상태 검증용 저폴리 기본 도형이다. 보스는 큰 각진 먹빛 껍질과 중심의 흑연 심으로, 약점 노출에는 화색, 그로기에는 정지한 균열광으로 읽힌다. 최종 몬스터 콘셉트 아트로 간주하지 않는다.
- `DESIGN.md`의 색·타이포·패널·발광 원칙을 유지한다. 기본 결정광은 `#68D5D0`, 선택/위험은 주홍과 위험색, `결: 화` 및 파훼 행동은 `#FFAD42`를 사용한다. reduced-motion에서는 상태 전환의 텍스트와 정지된 시각 상태를 유지하고 반복 발광·이동 연출은 하지 않는다.

## 아키텍처 경계

- `game/`에는 순수한 지역 진행 상태, 지역별 엔티티 정의, 문 개방 판정, 보스 상태기계, 보스 피해/AI 예외를 둔다. `game/`은 Svelte·Threlte·Three.js를 import하지 않는다.
- 몬스터는 더 이상 하나의 전역 `content.monster`만 참조하지 않는다. 엔티티별 런타임 정의를 통해 오타 요정과 보스가 각자의 HP, 이동·공격, 드랍, 보스 수식으로 동작한다.
- 보스 상태기계는 타이머와 적중 결과만 받아 다음 상태·방어력·AI/공격 허용 여부를 돌려주는 순수 모듈로 분리한다.
- `scene/`은 현재 지역의 바닥·문·몬스터·플레이어를 표시하고, 클릭을 기존 `GameIntent` 큐로 보낸다. 장면은 진행 규칙을 직접 변경하지 않는다.
- `ui/`는 월드에서 만든 스냅샷만 표시한다. 목표 문구, 현재 지역, 보스 상태/남은 시간은 HUD 스냅샷에 포함한다.

## 검증 기준

### 자동 테스트

1. M4 월드는 `결: 화` 장착·화 변신 가능 상태로 시작하고, 보급함과 M3 제작 재료는 다시 요구하지 않는다.
2. 오타 요정의 처치는 기존 골드·`음` 보상을 한 번 적용하고 문을 연다. 정예는 5초 후 재스폰해도 문은 열린 상태다.
3. 잠긴 문은 전환하지 않고, 열린 문은 전투를 정리한 뒤 보스방으로 전환한다.
4. 보스는 단단한 심에서 기존 피해 감소와 추적·반격을 적용하고, 6초 뒤 약점 노출로 진입한다.
5. 약점 노출 중 비변신 적중은 그로기를 열지 않으며, 화 변신 적중은 즉시 그로기·방어력 0·피해 감소 해제·AI/공격 중지를 적용한다.
6. 약점 노출과 그로기는 각각 4초와 10초 뒤 단단한 심으로 복귀한다.
7. 보스 처치는 보상을 한 번만 지급하고 `cleared`를 유지하며 재스폰하지 않는다.
8. 기존 플레이어 자동공격, 이동, 추적, 반격, 골드·`음` 드랍, 일반/정예 재스폰 및 M3 진행 테스트는 회귀 없이 통과한다.
9. Svelte/TypeScript 검사, 프로덕션 빌드, 런타임 데이터 검증을 통과한다.

### 브라우저 QA

1. 데스크톱에서 완료된 M3 상태, 목표 스트립, 정예·문·보스방 전환이 읽힌다.
2. 보스의 단단한 심, 약점 노출, 화 변신 실패, 화 변신 성공 그로기, 격파 상태를 각각 확인한다.
3. 390px 폭에서 플레이어·타깃·목표·자원·화 변신 조작이 겹치거나 가로로 넘치지 않는다.
4. reduced-motion에서 상태 정보를 유지하고 반복적인 발광·전환 애니메이션을 제거한다.
5. 모든 임시 캐릭터·몬스터 도형이 최종 디자인으로 설명되지 않는다.

## 제외 범위

- 서버 권위 상태, WebSocket, 저장/불러오기, 멀티플레이, 실제 인스턴스와 맵 로딩
- 아르카디아·새벽 들판·마을 귀환, 완전한 퀘스트/대화/보상 시스템
- M3 첫 수집·제작 흐름의 채굴장 내 재구현

- 보스 투사체·소환·범위 패턴·플레이어 전투 불능/부활
- 최종 플레이어, 무기, 정예, 보스, 변신 외형 디자인
