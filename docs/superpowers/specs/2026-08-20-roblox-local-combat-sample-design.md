# Roblox 로컬 전투 샘플 설계

## 승인 상태

- 승인일: 2026-08-20
- 실행 환경: Roblox Studio의 로컬 Place
- 사용자 확인 방식: Studio에서 Place를 열고 `Play` 실행
- 외부 상태: Roblox에 게시하지 않음
- 목적: 독립 3D 제작 대신 Roblox 네이티브 제작 방식으로 Rune Dungeon의 핵심 전투 감각과 캐릭터 표현 가능성을 눈으로 검증

## 범위와 경계

이번 작업은 기존 Svelte·Rust 수직 슬라이스를 삭제하거나 즉시 Roblox로 완전 이전하는 작업이 아니다. 저장소 안에 독립된 Roblox 샘플을 추가하고, 사용자가 직접 플레이한 결과를 바탕으로 전체 전환 여부를 결정한다.

포함 범위는 다음과 같다.

- Roblox 네이티브 R15 플레이어 캐릭터
- Roblox 표준 `WASD` 이동과 `Space` 점프
- 회전할 수 없는 고정 아이소메트릭 카메라
- 작은 전투장 한 곳
- 대검 기본 공격 한 종류
- 먹물 슬라임 세 마리와 추적·공격·사망·재생성
- 서버 권위 공격 검증, 피해, 처치, `음` 지급
- 플레이어 HP, 보유 `음`, 변신 상태를 보여 주는 최소 HUD
- `음` 조건을 충족하면 켜고 끌 수 있는 화염 변신
- 짙은 남색 의상, 큰 대검, 주황 화염을 사용한 임시 아람 표현

다음 항목은 포함하지 않는다.

- Roblox 게시, 공개 경험 생성, 과금 또는 Robux 사용
- 클라우드 저장, DataStore, 계정별 진행 보존
- 실제 1~4인 온라인 세션 검증
- 제작, 인벤토리, 보스, 마을과 던전 전환
- 최종 캐릭터 메시, 커스텀 얼굴, 상용 애니메이션
- 기존 웹 클라이언트와 Rust 서버 제거 또는 마이그레이션

## 구현 방식 비교와 선택

### 선택: Rojo 기반 로컬 Place

Lua 소스와 프로젝트 구성을 저장소에서 관리하고 Rojo로 로컬 `.rbxlx` Place를 생성한다. 생성한 Place는 Roblox Studio에서 열어 `Play`로 확인한다. 코드 리뷰와 버전 관리가 가능하면서도 Roblox Studio의 실제 실행 결과를 바로 볼 수 있어 첫 샘플에 가장 적합하다.

### 선택하지 않은 방식

- Studio에서만 직접 제작: 최초 배치는 빠르지만 코드와 오브젝트가 Place 내부에 묻혀 수정, 비교, 자동 검증이 어렵다.
- Roblox 클라우드 제작: 실제 멀티플레이 테스트에는 유리하지만 지금은 게시 절차와 외부 상태 변경이 불필요하다.

## 프로젝트 구조

Roblox 샘플은 저장소의 별도 `roblox/` 영역에 둔다. 기존 `client/`, `server/`, `shared/`와 런타임 의존성을 공유하지 않는다.

- `default.project.json`: Rojo Place 트리와 서비스 매핑
- `src/shared/`: 공격, 변신, 적 설정처럼 서버와 클라이언트가 함께 읽는 안정 ID와 상수
- `src/server/`: 전투 판정, 슬라임 상태, 보상, 플레이어 상태의 최종 소유자
- `src/client/`: 입력, 고정 카메라, HUD, 공격과 변신의 시각 효과
- `src/server/world/`: 전투장, 조명, 스폰 위치, 임시 무기와 슬라임을 결정적으로 생성하는 코드

한 파일이 전투 판정, 월드 생성, UI를 동시에 소유하지 않는다. 공유 데이터는 상태의 복사본이 아니라 양쪽이 동일한 ID와 표시 값을 사용하는 계약으로 제한한다.

## 조작과 카메라

- 이동과 점프는 Roblox 기본 캐릭터 컨트롤러를 유지한다.
- 대검 공격은 마우스 왼쪽 버튼 또는 `F`로 요청한다.
- 화염 변신은 `Q`로 켜고 끈다.
- 카메라는 `Scriptable` 모드에서 플레이어를 따라가며 정통 아이소메트릭에 가까운 고정 yaw·pitch·거리 값을 사용한다.
- 플레이어는 카메라를 회전하거나 줌할 수 없다.
- 모바일과 게임패드 전용 UI는 이번 샘플 범위에 포함하지 않지만, Roblox 기본 이동을 유지해 후속 확장 경로를 막지 않는다.

## 전투와 보상

클라이언트는 공격 의도만 서버에 보낸다. 서버는 살아 있는 플레이어인지, 재사용 대기시간이 지났는지, 목표가 존재하는지, 공격 범위와 전방 각도 안에 있는지를 확인한다. 조건을 통과한 공격만 슬라임의 HP를 낮춘다.

대검 공격은 한 번 휘두를 때 가장 가까운 유효 슬라임 한 마리를 타격한다. 첫 샘플은 타격감과 권위 경계 확인이 목적이므로 콤보, 치명타, 언령 발동은 넣지 않는다. 정확한 피해와 재사용 대기시간은 이름 있는 설정값으로 두어 플레이 후 조정할 수 있게 한다.

먹물 슬라임은 가장 가까운 살아 있는 플레이어가 감지 범위에 들어오면 추적하고, 공격 범위에서 주기적으로 피해를 준다. 추적 한계를 넘으면 자기 스폰 위치로 돌아간다. 사망하면 공격 대상과 타이머를 정리하고, 처치한 플레이어에게 `음`을 지급한 뒤 일정 시간 후 같은 스폰 지점에서 재생성된다.

첫 실행 수치는 다음과 같이 고정한다.

| 항목 | 값 |
| --- | ---: |
| 플레이어 최대 HP | 100 |
| 대검 피해 | 50 |
| 대검 재사용 대기시간 | 0.9초 |
| 대검 사거리 | 9 studs |
| 대검 전방 허용각 | 120도 |
| 슬라임 최대 HP | 100 |
| 슬라임 이동 속도 | 8 studs/초 |
| 슬라임 감지 범위 | 35 studs |
| 슬라임 공격 범위 | 5 studs |
| 슬라임 추적 한계 | 스폰에서 55 studs |
| 슬라임 공격 피해 | 10 |
| 슬라임 공격 주기 | 1.4초 |
| 슬라임 재생성 | 사망 후 4초 |
| 처치 보상 | `음` 1개 |
| 변신 요구량 | `음` 3개 |

## 변신

서버가 플레이어별 `음` 수량과 변신 상태를 소유한다. 요구 수량을 채우지 못한 `Q` 요청은 거부하며 HUD에 필요한 현재 상태만 동기화한다. 조건을 채운 플레이어는 `Q`로 변신과 해제를 전환할 수 있다.

첫 변신은 R15 메시를 교체하지 않는다. 같은 캐릭터에 다음 상태 표현을 적용한다.

- 평상시: 짙은 남색 중심의 의상과 발광하지 않는 대검
- 변신 시: 주황색 `Highlight`, 몸 주변의 절제된 화염 파티클, 대검의 주황 발광

변신은 색만으로 구분하지 않는다. HUD 텍스트, 캐릭터 외곽선, 파티클을 함께 바꾼다.

## 시각 방향과 HUD

임시 아트는 `DESIGN.md`의 먹빛 결정 원칙을 따른다. 전투장은 어두운 먹빛 바닥과 금속성 경계로 구성하고, 상호작용과 `음`은 청록색, 화염 변신은 `#FFAD42`에 가까운 주황색으로 구분한다. 넓은 면에 고채도 색을 사용하지 않는다.

R15 기본 얼굴을 사용하며 커스텀 얼굴을 제작하지 않는다. 아람의 정체성은 둥근 머리 비율을 해치지 않는 짧은 검은 머리, 짙은 남색 의상, 등 뒤의 큰 대검, 화염 변신으로 표현한다. 임시 외형은 최종 캐릭터 디자인 승인으로 간주하지 않는다.

HUD는 Roblox 기본 폰트 범위에서 가독성을 우선하며 다음 정보만 표시한다.

- 좌상단: 플레이어 HP
- 우상단: 보유 `음`과 변신 필요 수량
- 하단 중앙: `공격: 좌클릭/F`, `변신: Q` 조작 안내와 현재 변신 상태

## 데이터 흐름과 보안 경계

1. 클라이언트가 공격 또는 변신 의도를 `RemoteEvent`로 전송한다.
2. 서버가 이벤트 종류와 인자 타입, 플레이어 상태, 시간과 거리 조건을 검증한다.
3. 서버만 플레이어 HP, 슬라임 HP, `음`, 변신 상태를 변경한다.
4. 서버가 Attributes 또는 제한된 상태 이벤트로 표시용 결과를 복제한다.
5. 클라이언트는 복제된 결과로 HUD, 카메라, VFX만 갱신한다.

클라이언트가 보낸 피해량, 보상량, HP, 변신 가능 여부는 신뢰하지 않는다. 예상하지 못한 이벤트와 잘못된 값은 상태 변경 없이 거부한다. 공격 요청은 서버 시간 기준 재사용 대기시간으로 제한한다.

## 오류 처리

- 필요한 Remote나 월드 컨테이너가 없으면 서버 초기화 코드가 명확한 오류를 내고 플레이를 잘못된 상태로 계속하지 않는다.
- 캐릭터 또는 Humanoid가 아직 준비되지 않은 입력은 조용히 무시하고 다음 정상 입력을 허용한다.
- 공격 중 목표가 사라지거나 죽으면 피해를 적용하지 않는다.
- 플레이어 퇴장 시 서버가 보관한 공격 시각과 상태를 정리한다.
- 슬라임 AI 한 개의 오류가 반복 루프 전체를 중단하지 않도록 개별 엔티티 상태를 분리한다.
- HUD는 Attribute가 아직 복제되지 않았을 때 안전한 초기 표시를 사용하되 게임 진행 값을 자체 확정하지 않는다.

## 검증 기준

다음을 모두 만족하면 첫 로컬 샘플이 완료된 것으로 본다.

- Rojo가 로컬 `.rbxlx` Place를 오류 없이 생성한다.
- Place가 Roblox Studio에서 오류 없이 열린다.
- `Play` 실행 즉시 R15 캐릭터와 전투장이 보인다.
- `WASD`, `Space`, 고정 아이소메트릭 카메라가 정상 작동한다.
- 좌클릭 또는 `F` 공격으로 범위 안의 슬라임만 피해를 입는다.
- 슬라임이 플레이어를 추적하고 공격하며 사망 후 재생성된다.
- 처치 시 서버가 플레이어의 `음`을 증가시키고 HUD가 이를 표시한다.
- 요구 `음`을 모은 뒤 `Q`로 화염 변신과 해제가 가능하다.
- 변신 상태가 HUD, 외곽선, 파티클, 대검 발광으로 구분된다.
- 클라이언트가 피해량이나 보상량을 임의로 확정하는 경로가 없다.
- Studio 실행 중 새 오류가 Output에 기록되지 않는다.

## 후속 결정

사용자가 이 샘플을 직접 본 뒤 다음 중 하나를 선택한다.

- Roblox 전환 진행: Rojo 구조를 유지하고 1~4인 로컬 서버 테스트, 제작, 보스 순으로 확장
- 시각 조정: 카메라 거리, R15 비율, 의상, 대검, VFX를 먼저 보정
- 전환 보류: 기존 Svelte·Rust 수직 슬라이스를 계속 개발
