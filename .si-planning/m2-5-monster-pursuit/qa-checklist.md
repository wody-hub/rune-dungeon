# QA 체크리스트: M2.5 몬스터 추적

## 대상 화면 정보

- 프로젝트: `rune-dungeon`
- 기능: M2.5 먹물 슬라임 감지·추적·정지·복귀
- URL: `http://127.0.0.1:5173/`
- 실행 명령: `cd client && npm run dev -- --host 127.0.0.1`
- 화면: Svelte 5 + Threlte 단일 WebGL 게임 화면
- 인증·백엔드·DB: 없음
- 기준 설계: `docs/superpowers/specs/2026-07-31-client-poc-m2-5-monster-pursuit-design.md`
- 제외 범위: 몬스터 공격, 플레이어 HP·피격·사망, 경로 탐색, 충돌, 애니메이션, 어그로 VFX

## 검증 계약

| 항목 | 기대값/규칙 |
|---|---|
| 이동 속도 | `4.2` world units/s |
| 감지 거리 | `3.0` 미만에서만 감지; 정확히 `3.0`이면 `idle` |
| 정지 거리 | `1.4` 이하에서 `engaged`; 추적 이동은 이 경계를 넘지 않음 |
| 추적 포기 | 플레이어 거리가 `4.5`를 초과하면 `returning` |
| 스폰 이탈 한계 | 스폰에서 정확히 `6.0` 이상이면 `returning` |
| 복귀 | 플레이어를 재감지하지 않고 정확한 스폰 위치까지 이동 |
| 복귀 완료 | 도착 틱에는 `idle`; 재감지는 다음 틱부터 가능 |
| 생명주기 | 생성·사망·리스폰 시 `idle`; 리스폰은 원래 스폰·최대 HP |

## 불일치 사항

코드, 승인 설계, 테스트의 값과 상태 전이는 일치한다. 이 기능은 클라이언트 단독 POC이므로 백엔드·DTO·DDL·인증 검증은 해당하지 않는다.

## 테스트 환경 및 증적 규칙

- Node.js `v22.12.0` 이상을 사용한다.
- 실제 WebGL2 컨텍스트가 생성되는 Chrome을 1280×720로 실행한다.
- 각 시나리오 시작 전 새로고침하거나 월드 상태를 초기화해 테스트 간 간섭을 제거한다.
- 화면 조작 검증은 실제 마우스 클릭·더블클릭·지면 클릭으로 수행한다.
- 정밀 경계값과 내부 FSM 검증은 개발 빌드의 `window.__world`에서 JSON 스냅샷을 수집한다.
- 스크린샷은 `.si-planning/m2-5-monster-pursuit/evidence/screenshots/`, 상태·콘솔 로그는 `evidence/logs/`에 저장한다.
- 실패 시 기대값, 실제값, 재현 단계, 스크린샷 경로를 반드시 기록한다.

## A. 초기 로드·렌더링

- [ ] A-1: `/` 접속 응답이 성공하고 1280×720 Canvas가 표시된다.
- [ ] A-2: WebGL2 컨텍스트가 생성되며 로드 후 콘솔에 `error`, uncaught exception, WebGL 초기화 실패가 없다.
- [ ] A-3: `slime-1`, `slime-2`, `slime-3`가 모두 살아 있고 `idle`이다.
- [ ] A-4: 세 슬라임의 초기 위치가 각각 `(3, 0)`, `(-3, 3)`, `(0, -4)`이며 최소 700ms 동안 변하지 않는다.
- [ ] A-5: 초기 HUD가 플레이어 `대기`, 자동공격 `OFF`, 대상 패널 없음으로 표시된다.

## B. 감지·추적·정지

- [ ] B-1: 플레이어와 `slime-1`의 거리를 정확히 `3.0`으로 두고 한 틱 이상 진행해도 슬라임이 `idle`이며 움직이지 않는다.
- [ ] B-2: 거리를 `3.0`보다 조금 작게 만들면 `slime-1`이 `chasing`으로 바뀌고 즉시 플레이어 방향으로 이동한다.
- [ ] B-3: `slime-1` 접근 중 `slime-2`, `slime-3`는 `idle`과 원래 스폰 위치를 유지한다.
- [ ] B-4: 충분히 추적시키면 플레이어와 약 `1.4` 거리에서 `engaged`가 되고 더 가까이 이동하지 않는다.
- [ ] B-5: 대각선 또는 큰 프레임 스텝에서도 플레이어와의 거리가 `1.4` 안쪽으로 오버슈트하지 않는다.
- [ ] B-6: `engaged` 상태에서 플레이어가 `1.4` 밖, `4.5` 이내로 이동하면 다시 `chasing`하고 추적을 재개한다.

## C. 추적 포기·스폰 복귀

- [ ] C-1: 추적 중 플레이어 거리가 정확히 `4.5`이면 추적을 포기하지 않는다.
- [ ] C-2: 플레이어 거리가 `4.5`를 초과하면 같은 틱에 `returning`으로 바뀌고 스폰 방향으로 이동한다.
- [ ] C-3: 플레이어가 가까워도 스폰으로부터 정확히 `6.0` 떨어진 슬라임은 `returning`으로 전환한다.
- [ ] C-4: `returning` 중 플레이어를 감지 범위 안에 두어도 복귀 방향과 `returning` 모드가 유지된다.
- [ ] C-5: 복귀 이동은 스폰을 지나치지 않고 원래 스폰 좌표에 정확히 도착해 `idle`이 된다.
- [ ] C-6: 플레이어가 스폰 근처에 있을 때 복귀 도착 틱은 `idle`이고, 다음 틱부터만 `engaged` 또는 `chasing`으로 재감지한다.

## D. 선택·자동공격 회귀

- [ ] D-1: 살아 있는 슬라임 한 번 클릭 시 선택 링과 대상 HP 패널이 표시되지만 자동공격은 `OFF`다.
- [ ] D-2: 선택한 슬라임을 더블클릭하면 자동공격이 `ON`이 되고 플레이어가 대상에게 접근한다.
- [ ] D-3: 이미 자동공격 중 같은 슬라임을 다시 더블클릭해도 자동공격이 꺼지지 않는다.
- [ ] D-4: 지면을 클릭하면 대상 선택과 자동공격이 해제되고 플레이어 상태가 `이동`으로 표시된다.
- [ ] D-5: 이동하는 슬라임을 선택·공격할 때 대상 위치 갱신과 플레이어 접근이 같은 화면 루프에서 자연스럽게 이어진다.

## E. 사망·보상·리스폰 회귀

- [ ] E-1: 슬라임 HP가 공격 타이밍에만 감소하고 대상 HUD의 HP 값과 바가 함께 갱신된다.
- [ ] E-2: 슬라임 사망 시 화면에서 숨겨지고 선택·자동공격이 해제되며 내부 모드는 `idle`이다.
- [ ] E-3: 한 번의 사망에 골드와 음 보상이 정확히 한 번만 증가하고 대기 중 추가 증가가 없다.
- [ ] E-4: 기본 리스폰 시간 후 슬라임이 최대 HP, 원래 스폰 위치, `idle`로 다시 나타난다.
- [ ] E-5: 리스폰한 슬라임을 다시 처치하면 새 생명 기준으로 보상을 다시 한 번 받을 수 있다.

## F. 범위·안정성·최종 회귀

- [ ] F-1: 슬라임이 `engaged` 상태여도 플레이어 HP·피격·사망 UI나 몬스터 공격 효과가 발생하지 않는다.
- [ ] F-2: 추적·복귀·전투·리스폰 전 과정에서 Canvas, HUD, 선택 링이 깨지거나 사라지지 않는다.
- [ ] F-3: 반복적인 추적↔복귀 3회 후에도 한 슬라임만 반응하며 좌표나 모드가 비정상 값(`NaN`, 무한대, 미정의)이 되지 않는다.
- [ ] F-4: 새로고침하면 플레이어, 세 슬라임, HUD, 재화가 초기 상태로 복원된다.
- [ ] F-5: 전체 시나리오 종료 시 브라우저 콘솔에 새 오류가 없고 페이지가 계속 응답한다.
